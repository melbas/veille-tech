## À retenir

- **nginx2root : 5 RCE pré-auth dans nginx** — 8.3 🟡 — Le chercheur Xint publie 5 CVEs de RCE à distance non authentifié dans nginx (CVE-2026-123007, 123634, 123633, 121810, 113425). La plus impactante ne demande **que HTTP/2 activé** — code vulnérable présent dans **toutes les versions 1.9.5 → 1.31.8** (2015→aujourd'hui). Chaînée avec une faille kernel Linux (SCTP) : **root sur l'hôte, évasion de conteneur Docker démontrée** sur IP publique AWS. Fix 1.31.9 **pas encore publié** à la date de l'article ; mitigation : désactiver HTTP/2 sur les ports exposés. Fiabilité 🟡 : CVEs numérotés + backports Ubuntu déjà en production (USN-8955-1), mais pas d'annonce officielle nginx/nginx.org dans ce que j'ai vérifié. **Action pour toi** : aucun nginx exposé internet dans ta stack directe (Vercel front, DB Contabo derrière firewall) — mais tout serveur auto-hébergé avec HTTP/2 est concerné, dont les CPE/box en général. À surveiller : la release 1.31.9.
- **IPv6 : le renumbering mal géré casse le réseau après chaque reconnexion PPP** — 8.2 ✅ 🎯 — Rétcit de debug pointu : quand le préfixe IPv6 délégué change (reconnexion pppd/ISP), networkd/systemd ne fait pas l'annonce de retrait du vieil préfixe exigée par **RFC 9096** → les clients gardent une adresse IPv6 morte et « Google ne marche plus » en IPv6. `odhcpd` (OpenWrt) implémente correctement la RFC ; networkd a l'issue ouverte depuis des années (patch non mergé), OPNsense a refusé. Pertinent pour tout CPE/routeur WISP : si tu déploies de l'IPv6 côté clients, le comportement par défaut des daemons RA classiques crée des pannes fantômes après chaque coupure ISP. https://savyasacheejha.com/posts/why-odhcpd/ · 18/11
